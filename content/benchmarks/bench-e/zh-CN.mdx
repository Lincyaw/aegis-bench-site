## 任务设定<About text="智能体在隔离的开发环境中处理一个小型 Python 代码库，获得与工程师完成同一需求时相同的信息与工具。" />

<Flow>
  <Step title="智能体获得">需求说明、完整的代码仓库，以及可执行的开发环境。</Step>
  <Step title="工作方式">可读取和搜索代码、新建和修改文件、执行命令并运行已有测试；不可访问外部网络。</Step>
  <Step title="需要提交">对代码仓库的修改，以及说明每处改动的 report.json。只能提交一次。</Step>
</Flow>

为 ledger 的 report 命令增加 JSON 输出：传入 --format json 时，以 JSON 对象输出各账户的合计与总计；不传或传入 --format table 时，输出保持现在的表格不变。
</Sample>

## 评估方式<About text="每道任务以不向智能体公开的测试与检查判定结果，所有模型在相同条件下运行。" />

<Flow>
  <Step title="提交内容">智能体提交的代码修改与 report.json，在全新环境中重新构建。</Step>
  <Step title="检查项">已有测试、新功能的测试、原有输出不变，以及已有测试未被改动。</Step>
  <Step title="计分">全部检查通过记为通过；报告每道任务的通过率。</Step>
</Flow>

<Facts>
  <Fact label="指标">通过率，数值越高越好</Fact>
  <Fact label="运行次数">每道任务每个组合运行 1 次</Fact>
  <Fact label="运行预算">单次运行至多 50 轮交互</Fact>
  <Fact label="统一条件">相同的评测框架、轮次预算与执行环境</Fact>
</Facts>

## 常见问题

<Faq>
  <Question title="评测结果如何复现？" open>公开任务、评测框架与运行配置均随版本发布，按[评测方法](/methodology)中的步骤即可在本地复现相同的结果。</Question>
  <Question title="改动已有测试为什么判为未通过？">已有测试描述的是原有行为。为了让测试通过而改写它，会掩盖对原有行为的破坏，所以单独检查。</Question>
</Faq>
